01
§ problem

You spot a UI bug in 2 seconds. Fixing it takes 20 minutes.

The bug is right there. You can point at it. But turning "point at it" into "commit a fix" is a chain of grep, inspect, guess-which-file, edit, wait, refresh — repeated dozens of times a day. That's the friction redev removes.

02
before  /  without redev
  1. 1. Spot the wrong padding in browser
  2. 2. Right-click → Inspect → find the class
  3. 3. grep -r "className" in your editor
  4. 4. Pick the right file from 3 candidates
  5. 5. Edit. Save. Wait. Refresh.
  6. 6. Realize it's the parent, not the child. Repeat.
≈ 20 min · repeated 40× a day
after  /  with redev
  1. 1. Press Cmd+Shift+E, click the element
  2. 2. Type: "padding bigger, add shadow"
  3. 3. Claude edits the file, browser reloads
≈ 20 sec · normal git diff you can review & commit

05
§ why the framework packages matter

You could just paste a <script> tag. Here's why you probably shouldn't.

·
The overlay is one JS file served from localhost:5050. You can load it with a raw <script> tag anywhere. The framework packages (redev-nextjs, redev-vite-plugin) exist because doing it manually has three sharp edges that will bite you:
·
01
The dev-only guard is easy to forget.
Ship <script src="http://localhost:5050/..."> to production and every visitor's browser tries to hit their own localhost. Best case: a broken request in devtools. Worst case: it collides with something else running on their machine. <RedevScript /> returns null when NODE_ENV !== 'development'. You can't ship it by accident.
02
The port is going to change on you.
Port 5050 in use? redev-cli auto-picks the next free port. If you hardcoded src="http://localhost:5050/...", your overlay silently stops loading. With the component, you just pass a prop: <RedevScript port={5051} /> — or nothing, if you keep the default.
03
Vite goes further: real source mapping.
redev-vite-plugin doesn't just inject the overlay — it walks your JSX at dev time and stamps data-redev-file and data-redev-line onto every element. When you click something, Claude gets the exact file path and line number instead of having to grep for a class name. That's the difference between a 2-second edit and a 15-second edit, every time.
·
└─ The raw <script> tag path exists as an escape hatch for frameworks we don't have a package for yet. If we ship a companion for your framework, use it.

§ a typical session

Your daily loop, from cold open.

After the one-time install, this is the shape of every session.

·

browser: Cmd+Shift+E · click · "bigger padding, add shadow"

✓ Button.tsx edited · browser reloaded

- className="p-2"
+ className="p-4 shadow-md"
$ git commit -am "tighten button padding"
switching projects?

Every project keeps its own <RedevScript />. In the new project: ctrl+C the old npx redev-cli, run it in the new one, open the new dev URL. Same port serves whichever CLI is running.

port collision?

redev-cli picks the next free port and prints it in the banner. Pass it to the component: <RedevScript port={5051} />. Or free 5050.

§ docs

Deeper reference, only when you need it.

·
▸ Using redev inside Claude Code (via MCP — recommended)

MCP is the good path. Set up once, then every click gets picked up automatically inside your existing Claude Code chat. No shell copy-paste.

1. Register redev with Claude Code (one-time)
you$ claude mcp add redev -- npx redev-mcp
2. Verify
you$ claude mcp list
redev: npx redev-mcp (stdio)
3. Use it

Open claude in your project. Click an element in the browser, submit a prompt, then in the Claude Code chat type:

check redev for pending requests

Claude calls get_pending_request, reads your click, does the edit, calls apply_change. Your browser reloads.

Tools redev exposes to Claude
  • • get_pending_request — read the current click + prompt
  • • apply_change — mark done, reload browser
  • • report_error — say why it couldn't be done
The redev-nextjs component API

Single named export: RedevScript. Props:

  • • port (number, default 5050) — override if redev-cli picked a different port

Returns null when process.env.NODE_ENV !== 'development'. Renders as a plain <script async> tag in dev. RSC-safe: no hooks, no client bundle, works inside Server Components.

Configuring the Vite plugin

Walks JSX and injects data-redev-file, data-redev-line, data-redev-component. Dev only.

redev({
  include: ['**/*.tsx', '**/*.jsx'],
  exclude: ['node_modules/**'],
})
The browser overlay: what triggers, what shows

Cmd+Shift+E toggles it. Hover highlights an element, click freezes it, panel opens top-right.

Panel shows: component name (if the Vite plugin is active), file path, line, current classes. Type a change, submit.

Runs inside a shadow-DOM-safe layer with a high z-index. It doesn't interfere with your app's event handlers.

Drop-box mode (no MCP)

Prefer copy-paste? The panel emits a claude -p '...' command with the full element context. Paste it in a fresh terminal, Claude Code runs headless, edits your file, writes .redev/completed.json, the daemon reloads your browser.

Add .redev/ to .gitignore — it's a scratch dir.

Troubleshooting

Overlay doesn't appear? Check the badge bottom-right. If it's missing, <RedevScript /> isn't rendering — verify NODE_ENV and dev-server restart.

Wrong element gets picked? Hold Alt while clicking to grab the parent.

Agent stalls? Confirm claude --version works and you're signed in. Tail .redev/log.md.

08
§ faq

Things people actually ask.

·
Q Is my code sent anywhere?
A No. Everything runs on your machine. Claude Code is a local subprocess using your existing session. There is no redev cloud.
Q Which frameworks work?
A Next.js and Vite+React have dedicated companion packages. Astro, SvelteKit, Remix, Nuxt, plain HTML — anything with a dev server that renders HTML — works via the raw <script> tag. Source mapping is best on Vite (plugin adds file/line attributes); other frameworks use element hints.
Q What does it cost?
A redev is MIT and free. The only cost is your Claude Code subscription — which you already pay for if you're reading this.
Q How is this different from browser devtools?
A DevTools changes vanish on refresh. redev edits your actual source. The change survives, ships, is a real git diff you can review.
Q Can it break my code?
A Every edit is a normal file change. Reject any diff with git checkout --. No auto-commit, no hidden state.
Q Does it work on production sites?
A No — dev only, by design. The Vite plugin and <RedevScript /> component are both inert outside development.
